# 环境配置指南 🔧

## 环境类型

### 开发环境 (Development)
- **默认设置**：`NODE_ENV=development` 或未设置
- **权限**：所有功能启用
- **用途**：日常开发、调试、内容创建

### 生产环境 (Production)
- **设置**：`NODE_ENV=production`
- **权限**：编辑功能禁用，确保内容稳定
- **用途**：面向最终用户的部署

## 🚀 快速配置

### Mac/Linux

#### 开发环境启动
```bash
# 使用现有启动脚本（默认为开发环境）
./start-mac.sh
```

#### 生产环境启动
```bash
# 设置环境变量后启动
export NODE_ENV=production
./start-mac.sh

# 或者直接运行
NODE_ENV=production node server/api.js &
NODE_ENV=production npm run dev
```

### Windows

#### 开发环境启动
```cmd
start-windows.bat
```

#### 生产环境启动
```cmd
set NODE_ENV=production
start-windows.bat
```

## ⚡ 权限控制详解

### 开发环境权限
- ✅ **容器编辑**：可以修改容器名称、属性
- ✅ **布局编辑**：可以创建、修改、删除布局
- ✅ **配置管理**：可以批量管理、导入导出、重置配置

### 生产环境权限
- ❌ **容器编辑**：禁用，防止用户意外修改
- ❌ **布局编辑**：禁用，确保布局稳定
- ❌ **配置管理**：禁用，保护配置安全

## 🔍 环境检测

系统会自动检测环境并在界面显示：
- 🟡 **开发环境** - 黄色标识，所有功能可用
- 🔴 **生产环境** - 红色标识，编辑功能禁用

## 📝 部署建议

### 开发阶段
1. 使用开发环境进行内容创建
2. 配置好所有容器、布局、物品
3. 使用配置管理功能进行验证和备份

### 生产部署
1. 确保配置完整且通过验证
2. 创建配置备份
3. 设置 `NODE_ENV=production`
4. 启动服务

### 配置迁移
```bash
# 开发环境导出配置
# 在布局编辑器 -> 配置管理 -> 导出配置

# 生产环境导入配置（需要先切换到开发模式）
NODE_ENV=development npm start
# 访问编辑器导入配置后，再切换回生产环境
```

## 🛠️ 故障排除

### 权限错误
**问题**：提示"权限不足：生产环境禁用XXX功能"
**解决**：检查 `NODE_ENV` 环境变量，确认当前环境模式

### 环境切换
```bash
# 查看当前环境
echo $NODE_ENV  # Mac/Linux
echo %NODE_ENV% # Windows

# 清除环境变量（重置为开发环境）
unset NODE_ENV  # Mac/Linux
set NODE_ENV=   # Windows
```

### API连接失败
**问题**：配置管理功能不可用
**解决**：确保API服务器运行在 http://localhost:3001

## 📊 功能对比表

| 功能 | 开发环境 | 生产环境 | 说明 |
|------|----------|----------|------|
| 游戏运行 | ✅ | ✅ | 基础游戏功能始终可用 |
| 容器名称编辑 | ✅ | ❌ | 点击容器名称修改 |
| 布局编辑器 | ✅ | ❌ | 可视化布局编辑 |
| 配置统计 | ✅ | ❌ | 查看配置数据统计 |
| 配置验证 | ✅ | ❌ | 检查配置完整性 |
| 导入导出 | ✅ | ❌ | 批量配置管理 |
| 配置重置 | ✅ | ❌ | 危险操作保护 |

## 🔐 安全考虑

1. **生产环境保护**：自动禁用编辑功能，防止意外修改
2. **API权限验证**：服务器端强制权限检查
3. **操作确认**：危险操作需要用户确认
4. **自动备份**：重要操作自动创建备份

这种设计确保了开发时的灵活性和生产环境的稳定性！
